## 解决什么问题

一个类有多个构造函数时，它们往往共享大部分初始化逻辑。C++11 之前只能二选一：要么把公共逻辑抽成独立的 `init()` 函数，在构造函数体里调用；要么在每个构造函数的成员初始化列表里重复写一遍。前者会让对象在“构造完成”之前出现一个可观察的中间状态，后者则容易在修改成员时漏改某个构造函数。

C++11 引入委托构造函数：一个构造函数可以在初始化列表里调用同类的另一个构造函数，把真实的初始化工作交给它。被委托的构造函数先完整执行，然后才执行委托者自己的函数体。标准提案为 N1986。

## 基础用法

在构造函数的初始化列表里写出同类类型名和参数列表，就是委托；不能再同时初始化其他成员。

<!-- compile -->

```cpp
#include <iostream>
#include <string>
#include <utility>

class Logger {
 public:
  Logger() : Logger("info") {}

  explicit Logger(std::string level) : level_(std::move(level)) {
    std::cout << "start " << level_ << '\n';
  }

 private:
  std::string level_;
};

int main() {
  Logger fallback;
  Logger custom("debug");
}
```

输出 `start info` 与 `start debug`。默认构造函数只负责选择默认级别，真正的成员初始化集中在一个地方。完整版本见 [`examples/cpp11/delegating_constructors.cpp`](../../examples/cpp11/delegating_constructors.cpp)。

## 进阶用法

**委托目标先完整构造。** 被委托的构造函数执行完毕后，委托者的函数体才开始运行；因此委托者可以在函数体里继续修改成员，但对象在委托期间已经是完整对象。

**初始化列表只能二选一。** 一旦写了委托，就不能再写其他成员的初始化器，否则编译失败。需要补充成员时，在函数体里赋值。

**委托可以形成链，但不能成环。** `A()` 委托 `A(int)`、`A(int)` 再委托 `A(int, int)` 是合法的；任何构造函数最终必须有一个不委托任何其他构造函数的“根”，循环委托是未定义行为。

**异常会向外传播。** 委托目标抛异常时，委托者不会继续执行，对象按构造失败的规则析构已经完成的子对象。

**委托与默认参数取舍。** 默认参数让一个构造函数覆盖多种调用形式，代码更少；委托更适合不同构造路径需要执行不同逻辑的场景，例如拷贝构造与值构造共享校验。

**模板构造函数也能被委托。** 被调用的目标按普通重载决议选择，包括构造函数模板；这正是变参转发场景的常见写法。

## 陷阱与边界

**委托后不能再初始化成员。** 初始化列表里同时出现委托调用和其他成员初始化器会直接编译失败；这不是警告，必须改写。

**循环委托是未定义行为。** 编译器未必能检测到间接环，跨文件或跨条件编译的委托链尤其要小心。

**委托目标必须已经声明。** 类的完整定义在成员函数体里可见，但在构造函数的初始化列表里，构造函数重载集按类作用域查找，目标必须在该点可见。

**不要在委托目标里依赖委托者的成员。** 被委托者执行时，委托者自己的函数体还没运行；任何“先设置标志再委托”的写法都不成立。

**MSVC 支持较晚。** 委托构造函数要到 VS2013（18.0）才可用；更老的 MSVC 仍需手工抽取 `init()` 函数。

**与聚合初始化互斥。** 一旦类有了用户提供的构造函数，就不再是聚合类型；需要聚合初始化的结构体不要引入委托构造函数。

## 库联动

- **`<utility>`**：委托构造常与 `std::move`、`std::forward` 配合，把参数原样交给目标构造函数。
- **`<string>`**：字符串级别的默认值是最常见的委托参数，注意传值后移动的时机。
- **可变参数模板**：变参构造函数委托时，参数包需要先解包到目标签名，fmt 的 `ostream_params` 是典型写法。
- **异常安全**：委托目标抛异常时，委托者按构造失败处理，已完成的成员会被析构。
- **默认参数**：能用默认参数表达同一套逻辑时，优先用默认参数；委托留给确实需要分开的路径。
- **abseil / fmt / mold**：分别展示默认构造、变参构造与拷贝构造三类委托入口。

## 横向对比

| 方案               | 代码复用       | 对象状态                 | 主要限制                         |
| ------------------ | -------------- | ------------------------ | -------------------------------- |
| 委托构造函数       | 高，语言保证   | 目标完成后即为完整对象   | 初始化列表不能再写成员，不能成环 |
| 辅助 `init()` 函数 | 中，手工维护   | 构造体执行前存在中间状态 | 容易漏调用，异常安全需自己保证   |
| 重复初始化列表     | 低             | 直接构造                 | 成员增加时要逐处修改             |
| 默认参数           | 高，单构造函数 | 直接构造                 | 不同路径需要不同逻辑时表达力不足 |

跨标准演进：C++11 通过 N1986 引入委托构造函数；C++11 同时收紧初始化列表语义，使委托与成员初始化的互斥规则明确；后续标准未再改变委托模型，C++20 的聚合初始化改动也不影响它。
