# ModernCppAtlas

> 从 C++11 到 C++26 的现代 C++ 特性图谱：**使用场景、真实项目证据、进阶用法、开源库联动**。

[![Status](https://img.shields.io/badge/status-planning-yellow)](todo.md)

## 这是什么

不是语法速查表，也不是 API 参考手册。每个特性回答四个问题：

1. 它解决什么问题，没有它时怎么写？
2. 真实开源项目怎么用它（可点击到具体 commit 与行号）？
3. 进阶怎么用，有哪些陷阱和边界？
4. 能和哪些开源库组合，组合的收益与代价是什么？

覆盖范围：C++11、C++14、C++17、C++20、C++23、C++26。

## 不是什么

- 不是 C++ 入门教程（假定读者会 C++03）。
- 不是 cppreference 的全量 API 索引。
- 不做性能排名，只引用可复现的公开数据。
- 不收录无真实项目证据的“纸上特性”。

## 内容结构

每个特性一个条目，固定七节：

| 章节 | 内容 |
|---|---|
| 解决什么问题 | 痛点与旧写法对比 |
| 基础用法 | 最小可编译示例 |
| 进阶用法 | 组合、泛型、性能相关细节 |
| 真实项目证据 | 项目 / commit / 文件 / 行号 / 用法说明 |
| 陷阱与边界 | 生命周期、未定义行为、可移植性 |
| 库联动 | 与 Abseil、Boost、fmt、Asio、TBB 等的组合模式 |
| 横向对比 | 替代方案与跨标准演进 |

## 证据标准

一条证据必须同时满足：

- 指向固定 commit（禁止 `main` 浮动链接）。
- 文件路径与行号可验证。
- 许可证为 MIT / Apache-2.0 / BSD 等宽松协议；GPL 项目只记录位置，不摘录代码。
- 排除生成代码、vendored 第三方代码与明显反模式。
- 至少一名人工审核者确认“用法典型且正确”。

证据分三级：

- `verified`：扫描器发现 + 人工复核，可进入正文。
- `manual`：人工提交，尚未自动校验，进入待审队列。
- `candidate`：自动发现但未复核，只出现在内部报告。

## 社区投稿与审核流程

接受社区投稿。流程如下：

1. **提交 Issue / PR**，使用条目模板，必须填写特性 ID、项目 URL、commit、路径与行号、许可证、用法说明。
2. **自动校验（CI）**：
   - commit 是否存在、路径与行号是否命中；
   - 许可证是否在白名单；
   - 摘录长度是否超限；
   - 示例代码是否在对应标准下编译通过；
   - 是否重复证据。
3. **双人复核**：
   - 领域审核：用法是否正确、是否典型、是否反模式；
   - 证据审核：可追溯性、许可证、上下文是否断章取义。
4. **定级与合并**：通过后标记 `verified` 并合并；有争议时以标准文本、提案或编译器实际行为为准，要求提供最小可复现示例。
5. **失效处理**：每月自动重扫，代码漂移或链接失效时降级为 `stale` 并发 issue，30 天内无人修复则移出正文。

## C++26 收录政策

已投票通过的提案与仍在讨论的草案都收录，但严格标记：

- `status: final`：已进入标准草案（Committee Draft）或已投票通过。
- `status: draft`：仍在演进，页面顶部显示“草案，可能变更”，并注明提案编号与编译器实验性支持开关。
- `status: removed`：被后续提案替代或移除，保留条目并指向替代方案。
